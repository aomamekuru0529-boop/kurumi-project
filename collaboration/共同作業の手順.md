# Gitを使わない共同作業

## 担当を決める

代表者を1人決め、その人が最新版のフォルダを管理します。
例：文章担当はexperience.js、デザイン担当はdesign.css、村の担当はtour.js。
styles.cssとapp.jsは複数の演出に関わるので、編集する人を事前に相談してください。
同じファイルを2人が同時に編集すると自動で統合されません。

## 作業前

1. 代表者から同じ版のZIPを受け取る。
2. 元のZIPを保存し、作業用フォルダへ展開する。
3. 担当ファイルと変更内容を共有メモなどに記載する。
4. 「変更メモひな形.md」をコピーして、自分の名前と元の版を書く。

## 変更を渡す

1. 手元で動作確認する。
2. 変更・追加・削除したファイルの一覧を変更メモへ書く。
3. 変更したファイルだけを、元のフォルダ構成を保ってZIPにする。
4. 変更メモも一緒に共有フォルダやメールなどで代表者へ渡す。

node_modules、dist、ダウンロード用ZIPは修正ファイルとして渡す必要はありません。
package.jsonを変更した場合はpackage-lock.jsonも一緒に渡してください。

## 代表者がまとめる

1. 現在の最新版をコピーし、日付付きのバックアップを残す。
2. 受け取った変更メモを読み、元の版とファイルの重複を確認する。
3. 同じファイルの変更が重なったら、丸ごと上書きせずVS Codeのファイル比較で確認する。
4. 同意した変更をソースへ反映する。削除されたファイルも確認する。
5. 依存ライブラリが変わった場合はnpm ciを実行する。
6. npm run editで全体験を確認し、npm run buildで完成版を作る。
7. source相当のルートファイル、scripts、vendor、tests、collaboration、dist、起動ファイル、説明を次のZIPへまとめる。
8. node_modules、.git、test-results、downloads、秘密情報はZIPへ入れない。
9. 「共同編集版02」のように版名を付け、全員に配る。

全員が次の版に切り替えてから新しい作業を始めます。
公開する場合は、完成版distを公開先へアップロードする作業を別途行います。
